# P07B7: Parking-lock input A frequency and mismatch need separate attention from pulse level

P07B7 is listed in Ford's TR9070 parking-lock position sensor table for input A's frequency-out-of-range or input-mismatch category. The generic intermittent/erratic title does not reveal that more specific architectural context.

## Identify the type of signal problem

The table separates this category from A pulse-width high or stuck-at-one, coded P07B4, and pulse-width low or stuck-at-zero, coded P07B3. It also has a separate consistency result, P07B5. A legal high/low signal level does not by itself validate pulse timing or the input relationship.

The source does not publish a numeric P07B7 frequency window. The range-sensor frequency values elsewhere in the document belong to another input and should not be borrowed for this parking-lock sensor.

## A signal code does not prove the lock's mechanical state

Preserve input A's signal status, the companion input information available from the controller and the exact failure report. A parking indication alone cannot establish that the sensor's timing and relationship checks passed. Nor can this code by itself demonstrate that the mechanical lock is securely engaged.

Verification requires the correct parking-lock diagnostic procedure and appropriate vehicle restraint precautions. The summary does not provide a universal probe point or justify moving or bypassing the mechanism. It establishes which signal category needs investigation while keeping pulse-level and mechanical-state conclusions separate.
