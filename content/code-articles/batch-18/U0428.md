# U0428: Steering-angle messages that fail validity or integrity checks

U0428 reports invalid steering-angle information received by the electronic brake control module in this GM implementation. The source gives several independent routes to the same code. Knowing which route failed is more useful than treating the generic description as an instruction to replace the steering-angle sensor.

## Four routes are not one missing-message test

Checksum and alive rolling-counter failures use a sliding-window threshold of eight failures in sixteen samples. Eight consecutive sequence errors provide the fastest maturation. Separately, an incoming steering-angle validity indication can trigger a one-count failure. Another route checks a data mask stuck at zero; its row describes an extended period but does not specify that period numerically.

These are received-data checks. A separate missing-message row appears on the preceding table, while missing steering-angle calibration is assigned C0051. Consequently, U0428 does not by itself establish either complete loss of the module or a need to perform calibration.

## Determine which information became unusable

Record the EBCM fault detail, steering-angle validity, checksum or sequence status, and whether the data mask changes. The table lists an incorrect sensor as one possible context for the data-mask route; that is a reason to confirm applicability, not evidence that any replacement sensor is necessarily wrong.

The enable conditions include a 9–16-volt supply window and recovery delays after power-mode changes or voltage disturbances. Bus-off conditions inhibit relevant paths. The listed diagnostic is Type C with no emissions MIL; that classification does not describe every possible brake-system warning. Preserve the module-specific failure detail before clearing the record.
