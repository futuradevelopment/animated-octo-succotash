# U0222: The driver's window code identifies the motor node, not the switch pack

SAIC's BCM table assigns U0222:87 to the driver window motor. This is distinct from the driver-door switch-pack communication code. The diagnostic target is the motor's expected message frame, which fails to arrive within the configured time.

## A shared LIN system still has separate identities

The monitor requires ignition on and normal LIN1 communication. The source does not publish the timeout duration on this page. A generic two-second value borrowed from another door code would add unsupported precision.

The documented response includes disabled window-regulator functions and a default signal value. A window that remains still can therefore reflect the control response to unavailable data. It is not enough, by itself, to establish a failed switch or jammed mechanism.

## What the workshop should distinguish

The common window procedure checks the corresponding motor-to-BCM connection path, then the motor and finally the BCM. Harness faults and controller faults remain alternatives to a motor failure. If multiple door communication codes appear together, their pattern should be preserved before resets; this page alone does not prove a common cause.

Current recovery requires one hundred consecutive expected frames, with history clearing after forty failure-free power cycles. A supported repair should identify why the driver's motor node stopped communicating and verify that the message path is stable. The code does not authorize forcing the glass or bypassing the window controls to test the motor.

This interpretation is limited to the cited MG4 UK manual revision; it does not establish applicability to every MG4 build or another manufacturer.
