# U0128: The restraint module can lose parking-brake messages

In the cited SAIC SDM chapter, U0128:87 means the restraint controller cannot receive the specified electronic parking-brake frame within two seconds. The source explains that the parking-brake function is integrated into the IBS and communicates with the SDM over CAN.

## The generic module name can hide integration

The catalog's park-brake control-module label does not necessarily identify a separate box. For this procedure, IBS integration is explicit. Choosing service information for a standalone parking-brake module would therefore miss the documented architecture.

The record belongs to the SDM as receiver. It establishes missing information at that controller, not a measured failure of a parking-brake motor. The source retains wiring, IBS and SDM causes.

## Recovery is not the same as historical aging

The current communication condition recovers after one hundred consecutive receptions of the corresponding frame. History has a separate forty-failure-free-ignition-cycle rule. Those criteria should not be reduced to a promise that cycling the ignition once repairs the fault.

The workshop sequence begins with network integrity and the SDM-to-IBS path before controller decisions. Because both restraint and brake systems are involved, any physical circuit work requires the full safety procedure and qualified personnel. Preserve the complete :87 code and both modules' records. This overview makes no prediction about airbag deployment or parking-brake safety from a communication code alone.

This interpretation is limited to the cited MG4 UK manual revision; it does not establish applicability to every MG4 build or another manufacturer.
