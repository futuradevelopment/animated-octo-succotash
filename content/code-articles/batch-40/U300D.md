# U300D: Ford transfer-case ignition input and a self-test trap

Ford's 2012 F-150 torque-on-demand transfer-case procedure gives U300D:11 a specific meaning: the transfer-case controller detects a ground-short condition on its run/start input. The same page warns that the code can set if the ignition is not in RUN during the self-test. Test setup must therefore be established before the fault is treated as proof of damaged wiring.

## Two ways to know the ignition position

The transfer-case control module receives a hardwired run/start input and a separate ignition-position message from the body controller over high-speed CAN. These two information paths allow a mismatch to be narrowed, rather than immediately replacing the transfer-case module.

Pinpoint Test L compares the KEY_POS_4X4 and KEY_STATUS_4X4 scan parameters with the actual switch positions. If both agree, the documented branch treats the system as operating correctly at that time and calls for normal-operation verification after clearing the record.

## The failed parameter determines the next check

A wrong KEY_STATUS_4X4 result directs attention to the specified fused hardwired feed and its circuit. A wrong KEY_POS_4X4 result leads to ignition-switch diagnosis under the steering-column procedure. Those branches are meaningfully different; a scan report that says only ignition input fault discards the information that selects between them.

The code alone does not prove a mechanical transfer-case problem. A technician should confirm the self-test conditions, retain both parameter observations and diagnose the selected electrical path using the correct vehicle diagram. After repair, the comparison and system-operation check should both pass. This explanation is limited to the documented 2012 F-150 4WD 3.7L configuration with the two-speed torque-on-demand system.
