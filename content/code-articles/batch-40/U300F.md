# U300F: Ford accessory-status comparison through the instrument cluster

U300F:62 identifies an accessory-state comparison failure in Ford's 2012 Fiesta intelligent-access ignition system. The remote-function actuator module receives the start/stop-switch input, commands ignition-related relays and compares that request with the ignition status returned by the instrument cluster over CAN. Disagreement can therefore involve the request, the powered circuits or the return message.

## Cluster communication changes the route

The factory procedure first asks whether the instrument cluster communicates during its self-test. If it does not, the technician checks its ignition and accessory supplies. When both supplies are present, the branch goes to communication diagnosis; absent supplies lead to the associated fused circuits and relays.

This is why a noncommunicating cluster should not automatically be called a failed network module. A missing supply can prevent the module from participating at all. Conversely, replacing an accessory relay does not resolve a bus problem when the cluster has the required power.

## Separate the two feeds

The procedure records the ignition-feed and accessory-feed results independently and uses them in later decisions. It also distinguishes relay operation from continuity in the relay-to-cluster path and the relay's ground. These are workshop electrical checks, not permission to bridge the ignition system.

Other cluster and remote-function module DTCs receive attention before this comparison fault is pursued alone. Verification should confirm coherent requested and reported ignition states, not merely restored radio power. Ford uses the same flow for several ignition-state comparison codes, so U300F does not have a standalone accessory-part replacement rule. The described logic applies to the cited Fiesta configuration.
