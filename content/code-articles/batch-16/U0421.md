# U0421: Suspension messages fail freshness or protection checks

U0421 is the invalid-suspension-data diagnosis in the cited brake controller. Unlike U0132's missing-message checks, these rows examine messages that have arrived and been unpacked. The relevant examples are trim-position offset and vehicle-level-control information.

## Freshness and protection are separate checks

An alive rolling counter matching the previous value increments a fault counter. Other branches evaluate checksum or protection-value integrity. The source specifies an eight-of-sixteen sliding-window threshold for the illustrated messages. That is not the same as waiting for a 250-millisecond absence of all traffic.

Startup, power-mode transition, reset and voltage-recovery windows suppress the monitor. Confirmed bus-off or recovery also changes eligibility. Consequently, a message error observed during an excluded transition cannot be interpreted without checking the controller's diagnostic state.

## Retain the failed message and subtype

Identify whether the receiver rejected freshness, checksum or protection information. A plausible suspension value can still be stale or incorrectly protected. Conversely, an invalid-data code does not by itself identify a physically damaged suspension component or prove that the sender module must be replaced.

The table names possible source, sender, wiring and receiver issues but supplies no single-cause verdict. Use the exact network service procedure to investigate. Verification should establish accepted protected messages after the relevant exclusion windows and complete the prescribed system checks. Clearing U0421 or observing active bus traffic alone does not prove that the data used by brake and suspension functions is trustworthy again.
