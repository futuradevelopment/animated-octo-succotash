# U0412: Vehicle-integration data is rejected by different receiving modules

The generic U0412 title names the battery-energy control module. This GM document uses the code for invalid vehicle-integration-controller data. The source-specific module name is retained; it should not be silently converted into proof of a battery-pack problem.

## The receiver determines the test

In the brake-controller section, serial-data-26 protection is checked through authentication and alive-counter behaviour. Those branches have different qualifications, including 0.3 and 0.5 second. They require valid communication conditions rather than treating every absent or undervoltage-affected frame as the same failure.

The transmission section uses an integrity-fault decision at forty out of eighty observations. It requires at least five seconds of stabilization, an active partial network, ignition voltage from 8.75 V up to but below 18 V and no active over-the-air programming state. U0073-related bus-off indication disables that check.

## Preserve module identity with the code

A diagnostic report that shows only U0412 can hide which of these tests failed. Record the storing module, message identity and power/network state before interpreting the event. Applying transmission thresholds to the brake controller would combine unrelated monitor contexts.

The source supports a data-integrity investigation, not replacement of a battery or integration controller. Verification requires the relevant receiving module to accept valid messages under its own prerequisites, followed by the specified functional checks. A code erase or a currently plausible battery reading cannot establish that the original protected-message failure is resolved.
