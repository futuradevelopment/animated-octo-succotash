# U045A: Parking-assist status fails safety, protection or continuity checks

U045A is the invalid parking-assist data code in this source. The monitored message is parking-assist status, and the brake controller checks protection-related status and alive rolling-count behaviour. The fault does not directly measure the distance-sensing performance of an individual parking sensor.

## Two kinds of rejected status

One branch checks the message protection value and a reported failure of safety/security validation. Another checks the alive rolling counter and continuous-operation status. Both use an eight-of-sixteen sliding-window threshold in the cited table.

Those labels describe the receiver's validation results. They do not establish the cause of the rejected message or prove deliberate interference. The source's possible areas include the signal source, sending module, wiring and receiving module.

## Power and recovery context remain important

The monitor excludes start mode and specified five-second windows following power-mode transitions, reset or voltage recovery. Bus-off and recovery states also suppress normal evaluation. Retain those conditions along with the failed message subtype before selecting physical tests.

A parking-assist display that currently looks normal does not demonstrate that the protected status was accepted by the brake controller. Verification should confirm both valid message status and the prescribed functional checks after the exclusion windows end. Use the exact vehicle network procedure rather than replacing parking sensors or a control module from the code alone. Erasing U045A is not evidence that automated parking or related braking support is dependable again.
