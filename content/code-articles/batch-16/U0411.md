# U0411: Drive-motor messages arrive with invalid freshness or authentication

U0411 is the invalid-data diagnosis for drive-motor powertrain information in the documented brake controller. It checks protected messages for freshness and authentication. A message can be received electrically yet still be rejected for these reasons.

## Two message-integrity questions

The alive-counter branch detects a counter that repeats its previous value instead of advancing as expected. The authentication branch checks the message authentication code. The listed brake-axle-torque information rows use a 0.1-second qualification; the serial-data-31 rows use 0.2 second.

The source also gives weighted counter thresholds with a plus-two-per-step notation. Those values should not be rephrased as a simple count of lost packets. Communication prerequisites include ignition on and no error-passive or undervoltage condition for the relevant checks.

## Keep received data and trusted data separate

Retrieve the protected message or failure subtype where available. A stale alive counter and an incorrect authentication value lead to different evidence requests, even though both invalidate received data. Normal-looking torque or gear information on a scan tool does not establish that the protected message passed its integrity checks.

The monitor does not identify a defective drive motor, a failed high-voltage component or a particular network cause. Use the exact network and controller procedure; do not access high-voltage equipment simply because a drive-control module is named. Verification should confirm accepted, fresh protected messages under eligible conditions and complete the required functional checks. Erasing U0411 alone does not demonstrate restored data trust.
