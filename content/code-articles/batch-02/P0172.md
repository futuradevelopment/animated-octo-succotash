# P0172: Rich fuel trim before and after purge is enabled

The cited GM P0172 monitor detects excessive negative fuel correction on Bank 1. Its long-term metric is centered on 1.0; values below that center mean the controller is reducing fuel. The strategy deliberately treats purge vapor differently before and after purge first becomes active.

## Passive and intrusive decisions

Before purge is enabled, a passive test can evaluate the non-purge long-term metric against 0.710. After purge starts, the controller may need intrusive segments that ramp purge off. The purpose is to determine whether the rich correction persists without the normal vapor contribution.

The table describes a three-of-five segment decision and intervals between segments that let purge resume. It also provides a 300-second delay after an intrusive test report. These are controller-managed diagnostic events, not instructions to repeatedly command purge off manually.

## Evidence worth preserving

Record whether the code arose before purge activation or during the intrusive sequence. A rich correction that changes with purge has a different interpretation from one that remains during non-purge evaluation. This is why a single idle fuel-trim number cannot reproduce the full judgment.

Check whether the intrusive test actually completed and whether related input faults prevented it. The page refers to P0171's enabling conditions but explicitly excludes its fuel-level requirement. After corrective work, verify fuel-trim behavior through the applicable passive or intrusive path. A code clear alone cannot show which path was tested or whether the rich correction returned.
