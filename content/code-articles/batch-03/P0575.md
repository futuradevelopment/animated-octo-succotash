# P0575: cruise input data can be present but invalid

P0575 covers the validity of cruise-switch information received from the BCM in the cited GM legacy-switch strategy. The engine controller checks message protection and rolling-count behavior. This is more specific than the generic description, cruise-control input circuit.

## Message integrity versus communication loss

The source requires communication with the BCM to remain available and the protected message to be on the bus. An arriving frame can still fail its protection-value or rolling-counter check. Accordingly, a scan tool showing that the BCM communicates does not establish that its cruise-switch data passes this monitor.

The conditions include RUN power mode, a running engine and battery voltage of at least 11 volts for the stated enabling interval. A stationary key-on check without the engine running therefore does not reproduce the complete documented operating context.

## Making the evidence useful

Record whether the complaint accompanies invalid cruise data, missing messages, or a switch state that is valid but unexpected. Those are different diagnostic observations; this code specifically directs attention to validity. The extracted table includes awkwardly rendered sample-count entries, so this explanation does not convert them into a universal timing rule.

Cruise is disabled and disengaged until the diagnostic passes and recovery conditions are satisfied. Valid-looking switch values immediately after an event do not demonstrate that those recovery conditions have occurred. Use the exact vehicle's network and cruise diagnostic procedure to establish why the protected data failed, rather than assuming that replacing the physical button will correct a message-integrity fault.
