# P0606: processor-integrity faults require the reporting module

P0606 is a processor-related code with multiple documented internal triggers. The ECM example includes interprocessor communication checks, arithmetic checks, configuration comparisons, stack errors and error-correction hardware tests. The EBCM example separately describes operating-system, processor and configuration integrity checks.

## Why the generic title is insufficient

In the ECM, failure to receive a new seed within 450 milliseconds is one listed path. A seed arriving in the wrong sequence has a separate sample rule. These are internal coordination tests, so the code cannot be interpreted as proof that a particular vehicle sensor delivered the wrong value.

The EBCM rows under P0606 include restricted-memory access, unsupported device or software identification, processor exceptions and missed execution windows. Other brake-booster rows above the P0606 label on the page are not automatically part of this code.

## Preserve the diagnostic context

Identify whether the engine controller or brake controller stored the event, then retain any available failure subtype and companion codes. A symptom occurring at the same time may be an effect of the controller response rather than the specific failed self-test.

These tables do not specify a universal module replacement or programming fix. Brake-controller faults require the appropriate professional service process. Verification must exercise the relevant internal test after the actual cause has been resolved; a single successful engine start is not evidence that every processor-integrity path passed. Both cited sections classify the documented fault as Type A over one trip.
