# U031C: GM brake-module software compatibility mismatch

The cited GM BSC1 monitor defines U031C as software incompatibility with brake system control module B. Its specific evidence is a mismatch between an iBooster compatibility-index signal and the configuration expected by the stability-control system.

## Communication can exist while compatibility fails

The monitor evaluates an incoming brake-assist compatibility index. It therefore differs from a simple no-communication fault: a message can arrive, yet identify a software/configuration combination that the receiving controller does not accept.

The enable conditions require active CAN sending/receiving, no bus-off fault, suitable supply voltage and a delay after a power-mode transition. Those prerequisites help separate a valid incompatibility check from an unstable network startup. A historical U031C should be interpreted alongside power and communication faults, rather than in isolation.

## The code does not identify a mechanical booster failure

Its subject is compatibility of controller information. The table does not prove that the booster mechanism, pedal sensor or hydraulic system needs replacement. Confirm the installed module identities and applicable software/configuration through the vehicle manufacturer's service process before selecting any programming or component action.

The documented row uses a short qualifying duration and a one-trip classification. That does not make an arbitrary reflash a validated repair. Brake-system programming requires the correct vehicle-specific procedure and qualified service support.

After the actual mismatch is corrected, confirmation should establish compatible brake-assist information on an otherwise healthy network. Merely clearing memory or observing that the module responds to a scan tool does not prove its compatibility index is accepted.
