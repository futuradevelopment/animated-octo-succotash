# P0D08: Ford infers a positive charging contactor that remains closed

P0D08 identifies the positive charging contactor's stuck-closed category in Ford's documented PHEV system. The controller infers the condition from voltage information after an open command. The code does not mean a technician has physically inspected the contactor or proved that its contacts are welded.

## An open command changes the expected voltage relationship

Ford compares the high-voltage measurement reported by the battery charger control module with battery-pack voltage. If the reported measurement remains above pack voltage minus 20 volts for three seconds, the listed failure condition is met. At initial power-up, the corresponding time is six seconds.

That longer initial interval is an important distinction. A stored result should be interpreted with the operating stage, not by applying one universal delay to every observation. The comparison is also relative to pack voltage; it is not an absolute 20 volt threshold for a service probe.

## The inferred state is separate from the driver circuit

Ford gives the charging-contactor control electronics their own circuit and current-related codes. P0D08's voltage-based result concerns the apparent switched state after the command, while another code may describe how the coil driver behaves. Both kinds of information can be relevant to a complete diagnosis.

The negative charging contactor has a neighboring stuck-closed report using the same documented voltage logic. That shared observation does not authorize inferring a unique physical failure location without the applicable procedure. Verification must account for the commanded state, valid reported voltages and the complete high-voltage sequence. A fault-memory clear or an apparently completed charge session cannot establish that the contactor has safely opened.
