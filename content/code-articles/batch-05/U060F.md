# U060F: the air-flow sensor loses particular LIN messages

U060F is a LIN communication fault for mass or volume air-flow sensor A in the cited GM strategy. Two response types have different deadlines: MAF_Rsp_Press_2B_C03 uses 62.50 milliseconds, and MAF_Rsp_TmpHum_2A_C03 uses 250 milliseconds.

## Why one displayed reading can mislead

The different response types show that this connected sensor supplies more than one monitored stream. A plausible scan value does not prove all required messages are current. The code is not, by itself, evidence that measured air mass disagrees with actual airflow or that the sensing element is contaminated.

Monitoring requires an initialized LIN module, an enabled LIN channel and a slave configured as present. General power and transition conditions must be met for at least three seconds. The document lists a 500-millisecond communication loop and Type A, one-trip reporting; the loop period is separate from each message's allowed age.

## Narrow the investigation

Determine which information stopped updating and whether other devices on the relevant communication path were affected. That can distinguish a single missing response from a wider availability problem without claiming a specific failed part.

Verification should cover both monitored response types while the diagnostic is enabled. A normal idle-airflow number or successful code clear does not substitute for restored message delivery. Confirm the actual vehicle's sensor architecture before applying these LIN-specific criteria.
