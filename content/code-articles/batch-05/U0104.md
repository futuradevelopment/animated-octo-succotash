# U0104: cruise-control messages stop reaching the ECM

U0104 records lost cruise-control-module communication in the cited GM ECM strategy. The two listed messages, $2CB and $2CD, each fail when not received for more than 500 milliseconds. This is a message-arrival test, not a direct test of a cruise switch or actuator.

## Reporting and prerequisites

The table classifies this implementation as Type C, one trip, with no emissions MIL. A missing check-engine lamp therefore does not contradict the presence of a stored communication fault. That classification does not establish whether a driver-assistance feature is available or safe to use.

Monitoring depends on the channel requesting full communication and normal CAN transmission being enabled. A relevant Bus A, B or sensor-bus off fault must be inactive. The enabling state must persist for at least three seconds, and a pending accessory-to-off transition is considered.

## Diagnostic direction

First distinguish an absent cruise module from a receiver that lacks its periodic messages. Compare this ECM record with module availability and other network faults. The combination can guide a network investigation without prematurely identifying a failed cruise-control unit.

Retesting should cover the conditions in which the 500-millisecond message requirement applies. Successful cruise operation on one attempt is incomplete verification of an intermittent communication problem, while a diagnostic session outside the enable conditions may not evaluate it at all. The source provides no vehicle-specific connector or replacement procedure.
