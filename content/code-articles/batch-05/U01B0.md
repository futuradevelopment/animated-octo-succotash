# U01B0: battery-monitor LIN messages stop arriving

U01B0 is a loss of communication with the battery-monitor module on LIN in this GM ECM section. The table monitors several battery-information messages with different absence limits. Measured-temperature and MVI messages use 625 milliseconds, amp-hour messages use 1,250 milliseconds, and several figure-of-merit messages use 5,000 milliseconds.

## Why battery condition and communication are different

The code establishes missing digital information; it does not establish that the battery itself failed a capacity test. The variety of deadlines also means a module may lose one monitored information stream before all its data time out.

Monitoring requires the LIN channel to be enabled, the LIN module initialized and the slave configured as present. General power and transition conditions must have been satisfied for at least three seconds. The row lists a 500-millisecond LIN communication loop and Type B, two-trip reporting.

## Evidence that narrows the investigation

Check whether the configured battery-monitor module is actually expected on this vehicle, then compare message availability with the event's supply and power-state record. A configuration mismatch and an intermittent loss from an installed module demand different investigations; the DTC alone does not choose between them.

Verification means the required battery-monitor information is received while communication monitoring is eligible. A normal battery-voltage reading from another module cannot prove this LIN connection has recovered, because voltage measurement and message transport are separate observations.
