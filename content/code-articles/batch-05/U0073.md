# U0073: the ECM detects repeated Bus A off events

U0073 reports a communication-bus state, rather than one missing message from a named module. The cited GM ECM row monitors Bus A and counts bus-off failures. It lists at least 10 counts and a 100-millisecond window, with the diagnostic operating in a 12.5-millisecond loop.

## Why this changes the first question

A bus-off result can affect interpretation of several lost-communication codes. The question is whether the reporting controller's Bus A communication was available at the event, before assuming each missing module independently failed. The code itself does not locate a wiring defect or identify a controller for replacement.

Power state matters. The enable logic includes battery and run/crank voltage conditions, full communication state and whether an accessory-to-off transition is pending. The page contains several alternative power-mode branches; treating one voltage number as the complete enable rule would misread it.

## Verification

Keep the reporting-module identity and the distribution of other network faults. A cluster of faults from controllers using the same channel is diagnostically different from one recipient's isolated timeout; that is an inference to investigate with the correct network diagram.

This ECM implementation lists Type A, one-trip reporting. Verification requires restored communication during an eligible power state and no renewed bus-off count accumulation. A module that happens to answer a scan once does not establish that the short monitored event has disappeared.
