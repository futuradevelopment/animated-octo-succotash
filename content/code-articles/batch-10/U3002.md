# U3002: missing VIN programming versus a VIN mismatch

U3002 can identify either an unprogrammed vehicle identification number or a programmed VIN that disagrees with the network VIN. The cited front-camera and VPM tables explicitly distinguish those conditions.

## Two different tests

For the unprogrammed case, the stored EEPROM VIN consists entirely of the erased-memory value 0xFF. For the mismatch case, a stored digit differs from the VIN transmitted over GMLAN, and the stored VIN is not all 0xFF. That second requirement prevents blank memory from being mistaken for a legitimately programmed but incompatible identity.

Both are startup checks in the documented configuration. They require Run mode, supply voltage between 9 and 16 volts, the respective enable, and an OBD manufacturer-enable counter of zero. A continuous observation of network traffic after startup does not establish that the startup identity check ran successfully.

## What to verify

Obtain the reporting module and failure subtype, then compare its programming state with the vehicle’s legitimate identity using the appropriate service procedure. The code does not establish why an identity is absent or mismatched; it should not be treated as evidence of theft or a particular replacement history.

Verification means the relevant module retains the correct programmed identity and passes the applicable startup comparison. These are safety, non-MIL, emissions-neutral diagnostics in the source, so engine-lamp behavior is not an adequate confirmation.

## Documentation and applicability

This explanation is limited to the cited sections of GM’s 2025 25OBDG04B file. The file does not establish that this monitor or calibration applies to every vehicle; confirm the reporting module and vehicle-specific service information.
