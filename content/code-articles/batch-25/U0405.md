# U0405: cruise-control status arrived with the wrong data length

U0405 in the cited 2020 GM engine-controller table identifies an adaptive-cruise display/status frame received with the wrong data length. The problem is a message-format mismatch, rather than the absence of all communication from the cruise controller.

## Receipt does not establish usable data

This distinction matters when a scanner can communicate with both controllers. Module access shows that some communication is possible; it does not prove that the specific adaptive-cruise frame has the expected format for the receiving calibration.

The table requires the wrong-length condition to persist for half a second with ignition on and the referenced basic enable conditions satisfied. A single communication snapshot cannot reconstruct that complete result.

## Match the message to the actual implementation

The source names a particular high-speed adaptive-cruise status frame. It does not identify a failed radar unit, a wiring location or a universally applicable software update. Those conclusions require the full vehicle service procedure and configuration evidence.

Recording the reporting controller, companion communication codes and recent module/configuration work can help the technician investigate the mismatch. That is an editorial inference from the format check, not proof that programming caused it.

GM lists no MIL illumination for this row. An unlit check-engine lamp does not establish that adaptive cruise is available. Repair verification should confirm correctly formatted message reception under enabled conditions and follow the vehicle's assistance-system warnings, rather than rely only on clearing the stored code.

## Application limits

Document-level 2020 GM diagnostic table; per-code vehicle/engine/calibration applicability not established.
