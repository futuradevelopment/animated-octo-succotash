# C1055: ABS communication interruption calls for network diagnosis

## The network condition can occur in either direction

The Ariya C1055-49 table describes interruption of continuous ABS CAN communication, with transmit and receive conditions listed separately. Each uses a duration of at least two seconds under the stated power-on conditions. The diagnostic focus is the communication line, not an identified wheel sensor or hydraulic valve.

The listed restrictions include stability, traction, assistance and regenerative-cooperation functions. A driver may therefore notice several system warnings from one communication problem. That pattern does not prove that each affected function has suffered a separate component failure.

## Use the complete network picture

Nissan directs diagnosis to the CAN troubleshooting flow and distinguishes current from past status. The factory note specifically rejects replacing the ABS actuator and control unit solely for a historical occurrence. Preserving the complete scan helps the technician determine which modules were reporting communication problems at the same time.

Confirmation uses the specified sleep interval followed by power-on without READY. An immediate rescan during module wake-up is not the same observation. Recent supply or connector work is useful history, but should remain a lead rather than an assumed explanation.

Any actual loss of braking assistance or abnormal brake behavior requires professional assessment before driving. This article does not provide network bypass instructions or certify braking performance; it explains why the source prioritizes communication-system evidence over replacing the module named in the code.
