# P15B8: Find why the VCM lost the power-distribution message

## A missing message has a named sender

The Ariya VCM's P15B8-87 monitor expects CAN information from the IPDM E/R while the power switch is on. Its listed detection time exceeds two seconds. The possible causes include the communication circuit, the IPDM E/R and the receiving VCM, so the code identifies a communication relationship rather than a proven failed module.

Nissan begins diagnosis with the CAN circuit. If that investigation is satisfactory, the next step is the IPDM E/R's own diagnostic result. A fault stored there receives its specific procedure before the receiving VCM becomes the focus.

## An intermittent message needs evidence before erasure

The later flow includes an intermittent-fault simulation and only conditionally reaches VCM replacement. This sequence explains why a single stored communication code is inadequate grounds to order either controller. An interruption can be visible at the receiver while its cause lies elsewhere in the path.

Preserve a complete scan and the operating event, including whether the complaint followed electrical work or an unexpected shutdown. Those observations do not prove a cause, but help reproduce an intermittent condition. The published power-on confirmation is also distinct from checking whether a historical code disappears after memory is cleared.

The confirmation waits at least ten seconds after power-on before checking EV/HEV. That gives the specified missing-message monitor time to operate and is different from relying on a scan taken immediately as modules wake.
