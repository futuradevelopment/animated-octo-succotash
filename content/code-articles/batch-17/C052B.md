# C052B: One ABS pump code can represent several different driver checks

C052B is a broad ABS pump-motor control performance result in the cited GM brake controller. Its tables associate the same code with several driver checks. A diagnosis based only on the five-character display can therefore combine events that need different evidence.

## Identify which monitor reported the fault

One branch watches the motor-driver serial interface. Incorrect clock-edge counts or parity can cancel a write and set the transfer-error status. Another evaluates the disable path: after a prerequisite phase-state test, the controller changes its enable state and compares motor-terminal feedback with motor supply. That branch uses two failed counts, rather than the serial branch's 390-millisecond maturation.

The document also covers excessive driver temperature and a bridge diagnostic using a brief internally generated pulse. These are controller-managed tests, not instructions to pulse the pump externally.

## Preserve the subtype and operating state

The useful next distinction is whether the event concerns communication integrity, failure to disable, thermal status or bridge feedback. Record the brake module's expanded fault information and test state before interpreting a motor-voltage trace. A voltage reading cannot explain invalid serial parity by itself.

Several branches require valid driver communications and completed self-tests. Evidence collected before those prerequisites are satisfied cannot demonstrate the same pass or failure. The tables do not establish which board component needs replacement, and brake hydraulic or driver testing requires the applicable professional service procedure.
