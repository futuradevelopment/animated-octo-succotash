# U0139: suspension-module messages have two different timeout windows

U0139 is generically lost communication with suspension control module B. The cited ECM table names the sender SADS and monitors two CAN messages. Message $035 is allowed up to 10,000 milliseconds before the failing comparison, while message $364 has a much shorter 325-millisecond limit.

## One label hides two timing requirements

Those unequal windows matter during intermittent communication. Seeing one occasional message from the suspension controller does not prove the faster message is arriving frequently enough. Likewise, a short trace that never includes the slower message may be too brief to establish its timeout.

The diagnostic runs in a 12.5-millisecond loop. Full communication and normal CAN transmission are required, with the applicable bus-off condition absent and five seconds of qualified general enable conditions. A sensor-bus implementation additionally requires its relay on.

## Diagnose reception before suspension mechanics

Preserve which message timed out and whether other modules lost communication at the same time. The code identifies absent information at the receiver; it does not directly establish an actuator, damper or height-sensor fault. A common network interruption should be separated from a sender-specific interruption using the full event pattern.

Verification should include both $035 and $364 over their respective time windows while the monitor is enabled. A brief successful module identification request is not equivalent to healthy periodic messaging. The source does not publish a universal network location or support replacing the suspension controller solely from the generic lost-communication title.
