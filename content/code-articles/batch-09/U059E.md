# U059E: engine-out NOx sensor A data fails protection checks

The U059E row identifies NOx sensor A information through engine-out signal names. The monitored data includes oxygen information, NOx concentration, sensor status, error information and component information. The controller checks rolling counts, checksums and protected values while the corresponding frames are present.

## Not every field uses the same failure count

The main engine-out measurement and error checks use eight failures out of 18 samples. The continuation assigns three failures out of ten to additional data and component-information checks. The ECM executes the monitor in a 12.5-millisecond loop after five seconds of qualified voltage and power-transition conditions.

This is an integrity diagnosis, not a direct high-NOx or sensor-drift test. A concentration that appears excessive is not reliable performance evidence if the message carrying it fails its protection check.

## Preserve measurement and message status together

Determine which engine-out field is rejected. A status-message checksum error and a concentration protection failure can affect interpretation differently, though both reach U059E. Also distinguish invalid received data from a complete missing-message event.

Verification should establish accepted counter progression and protection across the affected engine-out fields. A single plausible NOx value or a successful diagnostic identification request does not verify the full stream. The source does not locate sensor A universally or prove that its sensing element, rather than another communication component, caused the failure.
