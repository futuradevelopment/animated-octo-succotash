# U053B: radar rejects protected host-vehicle path information

The generic U053B title refers to image-processing module A, but the selected long-range radar table names external object calculating module 1 as the sender. The monitored message is HstVehPathParms_Prtctd_MSG: protected host-vehicle path parameters.

## The path message must pass validation

The row describes invalid-data errors such as alive-rolling-count failures, with a 0.025-second fault maturation period. On the same page, U1616 separately monitors late arrival of the same host-path message on CAN 8. That distinction is useful: U053B here concerns message validity, while the neighboring code concerns timing/absence.

The receiver requires supply between 9 and 16 volts, its participating partial network active and more than five seconds after startup, reset or voltage recovery. The manufacturer enable counter must be zero. Depending on the downstream consumer, the default action can disable adaptive cruise or stop using radar information.

## Why radar hardware is not the automatic answer

The rejected information originates outside the radar and describes the host vehicle's path. A radar fault label therefore does not alone prove defective radar sensing. Identify the received message's counter/protection failure and compare it with sender, network and receiver-state evidence.

Verification should show the radar accepting the protected host-path stream under qualified operation. A normal radar target display does not validate this separate input. The source does not specify a programming repair or establish model applicability beyond the documented module section.
