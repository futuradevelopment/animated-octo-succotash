# U053C: processor-2 data-group integrity failures

U053C is generically invalid data from image-processing module B. The cited EOCM3 table instead names external object calculation module 1, processor 2, and lists H2H1DDG data-group integrity indications. Several groups use CRC8-related indicators, while group 5 uses a CRC16-related indicator.

## Data groups, not a camera picture

The strategy describes rolling-counter, checksum or message-authentication violations. The listed H2H1DDG groups use six failed messages out of ten. The table states an eight-second window within ten seconds based on the slowest signal transmission. A displayed camera image does not exercise these processor-data-group checks.

The monitor requires supply between 9 and 16 volts, an active participating partial network and more than five seconds since reset or a voltage-condition event. The manufacturer enable counter must be zero. The stated default action disables adaptive cruise and/or Super Cruise.

## Preserve which group fails

A CRC8-related group error and the CRC16-related group error identify different protected data groups, even though both can lead to U053C. Capture the available substatus before treating the code as a generic image-sensor failure. The table does not prove which processor, wiring path or software expectation caused the integrity indication.

Verification needs acceptable protection status across the implicated groups at the receiving controller. A successful module communication session shows availability but does not establish group integrity. Assistance-function validation remains separate from simply clearing this DTC.
