# U0620: exhaust temperature sensor 2 SENT messages are invalid or stale

The U0620 monitor is assigned to bank 1 exhaust gas temperature sensor 2. It evaluates SENT message faults and message age, rather than directly comparing exhaust temperature with a hot or cold limit. A message-fault value above zero is one failing route; the table also prints an age threshold above 100 seconds.

## Temperature availability is the first issue

Before using sensor 2 to assess exhaust conditions, determine whether its displayed value represents a fresh valid message. An unchanged temperature during a communication failure may be held or substituted, and does not demonstrate that the exhaust itself remained steady.

The source requires the calibrated initialization delay complete, valid run/crank conditions, no engine cranking and the diagnostic enabled. Confirmation uses 19 failed samples out of 25 at a 100-millisecond task interval. The table's age threshold should not be confused with that sample period.

## Use accompanying module evidence

The strategy says the related interface-module diagnostic depends on which module sensor 2 connects to. A sensor-specific timeout accompanied by a module fault can therefore identify a shared communication path requiring investigation. It does not establish a universal physical sensor location or justify replacing both items.

Verification needs sensor-2 updates that remain valid after initialization throughout enabled monitoring. Compare other channels only to understand whether the event is shared; a working sensor 1 does not verify sensor 2. Exhaust temperature performance and communication health remain separate questions.
