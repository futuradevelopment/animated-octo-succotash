# P2B83: charge-air cooler pump speed above its monitored range

The generic P2B83 description sometimes includes “air in system,” but the cited GM monitor directly evaluates pump speed. Its failure threshold is actual charge-air cooler coolant pump speed at or above 8,500 rpm. The table does not state that this result proves air is present.

## A qualified overspeed observation

The hardware must be configured as present, the diagnostic enabled and the pump enabled. Engine cranking must be absent. The source also requires no active pump communication-loss or response-fault condition, which matters because a speed value is useful only when its reporting path is credible.

Confirmation requires eight failing observations out of ten, sampled once per second. Thus, a short peak in a trace does not necessarily meet the recorded diagnostic's persistence rule. The table also qualifies the powertrain relay voltage or supply configuration; apply the actual vehicle's pump architecture rather than assume every pump shares the same feed.

## What the code does and does not establish

Compare the received speed with pump command and the contemporaneous communication status. A sustained reported overspeed and an implausible speed arriving through a troubled interface call for different investigations. The speed threshold alone cannot identify coolant level, bleeding needs, a mechanical defect or an internal controller fault.

Verification requires a valid speed report with the enabled pump operating below the failing range and the monitor completing. Any coolant-system service should follow the applicable filling and bleeding procedure, but this source does not authorize diagnosing trapped air solely from P2B83.

## Source and applicability

Documented 2025 GM gm-2025-04b monitor only; vehicle, engine and controller applicability must be established separately. [GM monitor table, PDF page 859](https://gsi.ext.gm.com/gmspo/mode6/pdf/2025/25OBDG04B.pdf#page=859).
