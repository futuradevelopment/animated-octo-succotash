# U029D: NOx sensor A messages have several distinct timeouts

The U029D monitor watches a group of CAN messages from NOx sensor A. The short-period group $0B0, $0B1, $0B5 and $0B7 has timeout limits above 1,025 milliseconds. Other messages use different windows: $289 exceeds 1,137.5 milliseconds, $296 exceeds 1,700 milliseconds, $591 exceeds 7,450 milliseconds and $293 exceeds 10 seconds.

## One response does not prove a complete sensor stream

Those different periods explain why a sensor can appear partly available yet still meet a missing-message condition. Record which message timed out rather than treating the generic code as proof that the entire sensor stopped working at once.

The diagnostic runs every 12.5 milliseconds after qualified general conditions have held for at least five seconds. Full communication and normal CAN transmission must be enabled, the relevant bus-off fault absent and the sensor-bus relay on where that bus architecture applies.

## Communication before concentration

A missing NOx-sensor message is different from a received concentration that is implausible or too high. Establish timely data delivery before using the NOx value to judge catalyst performance. A substituted or stale scan-tool concentration cannot verify the original stream.

Confirmation should cover the short and long message periods with the sensor powered and the network qualified. A brief diagnostic connection may miss the ten-second requirement. The source does not identify the sensor's exhaust location for every model or establish that the sensor assembly must be replaced from U029D alone.
