# U0075: CAN 1 bus-off detected by the EOCM3 receiver

U0075 is generically labeled communication bus C off. In the cited EOCM3 table, the channel is explicitly CAN 1. The diagnostic detects the CAN controller's bus-off condition, rather than the timeout of one named transmitting module.

## Bus-off is broader than one missing message

The source lists a decision over three seconds of a five-second window, evaluated every second. It requires RUN power mode, an active EOCM communication state and an enabled diagnostic. A bus that is intentionally inactive does not reproduce those prerequisites.

The table states that fault detection disables adaptive cruise control as an emissions-neutral default action. That can explain loss of that function without identifying the physical cause of the network event. A bus-off report alone does not select a failed radar, camera or engine controller.

## Read the network state first

Determine whether CAN 1 itself entered bus-off and whether other missing-message reports followed the same event. Investigating each absent sender independently can obscure a common channel failure. The original power-mode and communication-active status also help distinguish a genuine operating fault from a record around shutdown or reset.

The voltage inequality printed in this row is internally inconsistent, so it is not reproduced as a valid operating-voltage specification. Verification should use the applicable service voltage requirements and establish normal CAN 1 operation while the EOCM monitor completes. The generic bus letter must not be assumed to match every vehicle's physical network naming.
