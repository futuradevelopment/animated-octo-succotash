# U0402: transmission estimated-gear data fails protection checks

U0402 is invalid data received from the transmission control module. The selected BCM row specifically monitors the estimated-gear message's rolling count, TEGP_ARC, and its protected data field, TrnsEstGr_Prtctd. It requires 15 failed observations out of 16 samples for the listed checks.

## Invalid is different from missing

A rolling counter supports checking message freshness or expected progression, while the protected field supports integrity checking. This diagnosis is therefore not simply a timeout waiting for a silent transmission controller. A plausible displayed gear can still come from a stream whose protection checks fail.

The BCM executes the monitor in a 10-millisecond loop. It waits at least five seconds after startup, reset or voltage recovery, and requires three seconds of qualified conditions including an active partial network, RUN mode and battery voltage above 11 volts.

## Keep the reporting controller in view

Other receiving controllers use additional transmission signals and different count thresholds for U0402. Apply this article's 15-of-16 requirement only to the cited BCM implementation. The module storing the code is part of identifying the correct diagnostic.

For verification, confirm expected counter progression and valid protection on the estimated-gear message after qualification. A normal shift event alone does not prove message integrity. The source does not establish whether the TCM, communication path or receiver expectation caused the mismatch, so transmission replacement is not a conclusion supported by this code.
