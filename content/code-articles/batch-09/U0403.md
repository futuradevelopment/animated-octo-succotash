# U0403: transfer-case secondary-axle message fails integrity checks

The documented U0403 monitor checks information received from the transfer case control module. Its specific fields are SAP_ARC and SecAxl_Prtctd, the rolling count and protected secondary-axle data. Each uses a failure rule of eight observations out of 18 samples.

## A message must be available to be rejected

The source explicitly requires the frame containing the rolling count, protection value or checksum to be available on the bus. U0403 therefore describes a received-data integrity problem, not merely a transfer-case module that never answers.

Evaluation occurs in a 12.5-millisecond loop. The listed operating conditions must hold for at least five seconds, with battery voltage at least 11 volts and no pending accessory-to-off transition. These qualifications matter when the event occurs around startup or shutdown.

## What to investigate next

Preserve the secondary-axle message and the failed protection field if the diagnostic equipment exposes them. A repeated counter, an integrity mismatch and a complete frame absence are different observations and should not be merged into one generic network complaint. A mechanically normal transfer-case shift does not validate the received data's counter or protection.

Verification requires acceptable progression and protection of the relevant message while the receiver's monitor runs. The table supplies no transfer-case mechanical fault threshold, wiring location or programming remedy. It identifies which received information was rejected; it does not prove which module or network segment caused that rejection.
