# U0435: Rear-steering data is received but cannot be trusted

U0435 covers several invalid-data checks for the rear-steering module in GM's 2020 OBDG07 brake-controller table. It is broader than a simple missing-message fault: the receiver can obtain rear-steering messages and still reject their status, validity or integrity information.

## Different branches mature differently
One branch detects alignment not completed after ten consecutive messages, approximately 100 milliseconds. Another detects an operational status other than normal for 50 messages, approximately 500 milliseconds. A received actual-angle invalid flag can mature immediately in one message. Separate rolling-count and checksum checks use their own sliding-window failure logic.

These distinctions matter because “communication present” does not establish usable rear-steering data. An explicit unavailable status is different from corrupted message protection or an unfinished alignment status, and they should not be merged into a single assumption that the network is disconnected.

## Preserve the specific failing status
Record the relevant subfault or failure information, received rear-steering status and associated module diagnostics. The source excludes initial startup and voltage-recovery intervals and, for several branches, requires the specified supply-voltage range and no latched bus-off failure. A temporary transition outside those conditions is not the complete enabled result.

Verification should show valid rear-steering status and message integrity after the demonstrated cause is corrected, using the correct steering-system service procedure. The code does not authorize bypassing an invalid flag or selecting a replacement module. Alignment, source-module faults and communication integrity require different supporting evidence before any physical steering work.
