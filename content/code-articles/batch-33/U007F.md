# U007F: FlexRay bus-off state in the object-control network

GM's 2020 OBDG07 K2P object-controller table uses U007F for a bus-off condition on the FlexRay 1A network. The generic catalog labels this communication bus M; the supported OEM implementation should be identified from the vehicle's network architecture before any wiring is selected.

## A network-level state differs from one missing sender
The monitor detects the bus-off condition itself. That is different from one expected module's message timing out while the network otherwise communicates. A series of device-specific communication faults may therefore need to be interpreted in the context of this broader bus state.

The source requires RUN power mode, an active communication state in the object controller and enabled diagnostics. Its printed supply-voltage inequality is impossible as written, and the timing cells do not give one unambiguous failure-duration rule. Those values are deliberately not repeated as usable test limits; exact calibration service information must resolve them.

## Establish the network condition first
Confirm that the affected controller actually reports FlexRay bus off, then investigate the supported network path and module power states using the proper service procedure. Do not infer that one sensor or camera must be replaced simply because several of its messages are unavailable.

The documented response disables adaptive cruise control and/or Super Cruise on the supported architecture. Verification should establish normal bus participation and restored relevant communication after the actual cause is addressed. The unresolved source cells remain a review limitation, and this article is not a substitute for a complete FlexRay electrical diagnostic procedure.
