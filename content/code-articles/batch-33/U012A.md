# U012A: Chassis-control module A messages stop arriving

U012A monitors communication with chassis control module A in GM's 2015 OBDG08A table. The receiving controller expects a particular CAN message, identified as $4DB, and records a failure when it is absent for at least ten seconds under the enabled network conditions.

## A missing message is not an invalid measurement
The monitor checks whether the expected communication arrives. It does not directly measure a chassis sensor or establish that received data has an implausible value. A missing message and a message carrying invalid information therefore require different evidence, even if both affect the same vehicle function.

The source requires normal transmission on CAN bus A and excludes an active U0073 bus-off condition on the current key cycle. It also uses power-mode, voltage and network-management conditions before evaluating the loss. A module that is intentionally asleep during an excluded state should not be judged by the ten-second timeout alone.

## Follow sender, bus and receiver
Preserve which controller stored U012A and whether the expected message is absent at that receiver. Compare that with the sender's power and communication state using the proper network diagnostic procedure. The DTC alone does not prove that chassis module A itself is defective.

Verification should show that $4DB arrives through the qualified operating interval and the communication monitor completes after the actual cause is addressed. The table's 12.5-millisecond execution loop is the monitor's checking rate, not its ten-second missing-message limit. Exact module identity and vehicle applicability must be confirmed beyond this document-scoped GM implementation.
