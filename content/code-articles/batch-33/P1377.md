# P1377: Camshaft and 4X pulse counts disagree

P1377 compares camshaft-cycle information with the low-resolution 4X reference in GM's 1998 4.0L L47 Aurora table. The row evaluates a prescribed pulse count over two cam cycles, using 16 as the comparison count. This is a relationship between repeated events, rather than an isolated voltage reading.

## Counting needs complete cycles
The monitor requires engine speed above 496 rpm and more than seven cam edges since key-on. The source specifies four failures in ten tests, evaluated every 250 milliseconds. These conditions establish that sufficient engine rotation information is available before the controller judges the relationship.

When reviewing a captured waveform, preserve the full cam-cycle boundaries. Starting a count midway through a cycle or treating the table's two-cycle observation as one cycle can manufacture an apparent discrepancy. The code should direct attention to the relationship between the two streams, not merely whether either trace looks active.

## Missing, extra and misgrouped events
A useful investigation separates absent 4X events from additional events or a cam reference that divides the sequence unexpectedly. Those are different explanations for an incorrect count. The diagnostic itself does not prove that a mechanical timing component or a particular sensor has failed.

Verification should show a stable expected relationship across complete cycles using the exact vehicle service interpretation. Because the OEM row's phrasing combines “per CAM cycle” with “for 2 CAM cycles,” confirm the counting convention in application-specific service data before turning it into a bench-test specification. This article preserves that wording limitation instead of inventing a different ratio.
